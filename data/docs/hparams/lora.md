# LoRA: ранг и alpha

LoRA обучает низкоранговые добавки ΔW = B·A к выбранным линейным слоям. Ранг r задаёт ёмкость адаптера.
Для классификации и коротких ответов обычно хватает r = 4–16; для генерации длинных текстов и сложных
доменов — r = 16–64. Слишком большой r на малых данных (< 1000 примеров) повышает риск переобучения.

# LoRA: масштаб alpha

Эффективный масштаб обновления равен alpha / r. Распространённая практика — alpha = 2·r (масштаб 2) или
alpha = r. При варианте rslora масштаб считается как alpha / sqrt(r), что стабилизирует обучение на больших r
(r ≥ 32); с rslora можно не уменьшать lr при росте ранга.

# LoRA: learning rate

Стартовое значение lr для LoRA/QLoRA с AdamW — 2e-4 (Unsloth LoRA Hyperparameters Guide). Оптимальный lr LoRA
примерно в 10 раз выше, чем у полного дообучения той же модели, и почти не зависит от ранга (при alpha/r = const)
и от объёма данных (Thinking Machines, «LoRA Without Regret», 2025) — снижать lr на больших датасетах не нужно,
это лишь замедляет обучение. Для крупных моделей (hidden > 4096) — около 1e-4. Если loss скачет или уходит в NaN —
уменьшить lr вдвое и увеличить warmup. LoRA хуже переносит большой батч: эффективный батч 8–16.

# LoRA: какие модули адаптировать

Лучше адаптировать все линейные слои (attention + MLP: gate, up, down): LoRA только на attention проигрывает даже
при равном числе обучаемых параметров, основной вклад дают MLP-слои («LoRA Without Regret»). Набор attention
оправдан только при жёсткой нехватке памяти.

# DoRA

DoRA раскладывает вес на величину и направление и обучает их раздельно; часто даёт небольшой прирост качества
при малых рангах (r ≤ 8) ценой ~10–30% замедления шага.

# Число эпох

Для LoRA обычно хватает 1–3 эпох: больше трёх на инструкционных данных почти не даёт прироста и повышает риск
переобучения (Unsloth). Ориентир: < 1 тыс. примеров — до 4 эпох с ранним остановом, 1–10 тыс. — 3, 10–50 тыс. — 2,
больше — 1. Число эпох задаётся как верхняя граница: ранний останов прекращает обучение на плато.
