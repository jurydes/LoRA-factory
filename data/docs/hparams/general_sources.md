# Unsloth: рекомендованные значения LoRA

Руководство Unsloth по гиперпараметрам LoRA: начинать с r = 16 (пробовать 8, 16, 32, 64, 128), lora_alpha = r или
2·r, lora_dropout = 0, learning rate 2e-4 (осторожнее — 1e-4 … 5e-5), 1–3 эпохи (больше обычно переобучает),
эффективный батч около 8–16 (например 2 × накопление 4), adapter на всех линейных слоях
(q, k, v, o, gate, up, down), weight decay 0.01, warmup 5–10% шагов, линейный или косинусный шедулер.
При больших рангах (r ≥ 64) — rsLoRA.

# QLoRA (Dettmers et al., 2023)

Оригинальные настройки QLoRA: NF4 + double quantization, адаптеры на ВСЕХ линейных слоях (это ключевое для
качества на уровне полного дообучения), r = 64, alpha = 16, dropout 0.1 для моделей до 13B и 0.05 для 33B+,
learning rate 2e-4 для моделей до 13B и 1e-4 для 33B+, max grad norm 0.3, постоянный шедулер, эффективный батч 16.
Квантизация базы почти не снижает качество адаптера, но шаг на 20–40% медленнее.

# LoRA (Hu et al., 2021)

В исходной статье для понимания языка (GLUE) хватало очень малого ранга (r = 1–8) на q и v проекциях: обновление
весов имеет низкий внутренний ранг. Для генерации и сдвига домена ранг и набор модулей важнее.

# Практика Raschka по LoRA

Эксперименты Raschka (Practical Tips for Finetuning LLMs Using LoRA): включение LoRA во все слои влияет на качество
сильнее, чем рост ранга; alpha = 2·r — хорошее правило; многократные эпохи на статичном датасете могут ухудшать
результат (переобучение); результаты LoRA стабильны между запусками при фиксированных гиперпараметрах.

# Размер данных

Меньше 1 тыс. примеров: r = 8, lr 1e-4, 4–8 эпох с ранним остановом по val (данных мало — нужно больше проходов,
но высокий риск переобучения). 1–10 тыс.: r = 16, lr 2e-4, 2–4 эпохи. 10–50 тыс.: r = 16–32, 1–3 эпохи.
Больше 50 тыс.: 1–2 эпохи, lr 1e-4 … 2e-4; число эпох важнее не завышать, чем занижать.
