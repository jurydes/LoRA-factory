# Классификация текста (text_classification)

Ответ — короткая метка, модель учится отображать вход на несколько токенов. Достаточно r = 8–16; модули attention
обычно хватает, all_linear даёт небольшой прирост на трудных классах. lr 1e-4 … 2e-4, 2–4 эпохи (на больших датасетах
1–2). Длина последовательности определяется входом; ответ — до 5–10 токенов. Следить за дисбалансом: основная
метрика macro-F1, модель легко скатывается в мажоритарный класс (prediction collapse).

# Анализ тональности (sentiment_analysis)

Как классификация, но задача проще для предобученных моделей: базовая модель с промптом часто уже даёт заметное
качество, поэтому хватает r = 8, lr 1e-4 и 1–3 эпох; при большом датасете (> 20 тыс.) — 1 эпоха. Нейтральный класс
— самый трудный: смотреть per-class F1.

# Суммаризация (summarization)

Длинный вход (сотни–тысячи токенов) и длинный выход: max_seq_len по p95 длины статьи + резюме, gradient checkpointing
при нехватке памяти. Модули all_linear, r = 16–64, alpha = 2·r, lr 1e-4 … 2e-4, 1–3 эпохи. Эффективный батч 16+:
шумный loss на длинных последовательностях. Основная метрика ROUGE-L, переобучение видно по росту val loss.

# Генерация текста (text_generation: перефразирование, детоксификация, упрощение)

Перенос стиля при сохранении смысла: all_linear, r = 16–32, lr 2e-4, 2–4 эпохи. Вход и выход близкой длины.
Основная метрика chrF; ExactMatch низок по природе задачи.

# Распознавание сущностей (ner)

Генеративный NER: модель должна выучить строгий формат «ТИП: текст; …» и точные границы сущностей. Нужен адаптер
на всех линейных слоях, r = 16–32, lr 1e-4 … 2e-4, больше эпох, чем для классификации: 3–5 (формат и границы учатся
дольше), на малых датасетах — до 8 с ранним остановом. Ответ может быть длинным при многих сущностях — оставлять
запас в max_new_tokens. Основная метрика entity-F1 (точное совпадение типа и текста).

# Ответы на вопросы (qa, экстрактивный)

Контекст длинный, ответ короткий фрагмент: max_seq_len по длине контекста, all_linear, r = 16, lr 1e-4 … 2e-4,
1–3 эпохи (SQuAD-подобные датасеты большие — обычно 1–2). Основная метрика token-F1 (SQuAD), модель склонна отвечать
лишним текстом — следить за ExactMatch.

# P-tuning

P-tuning обучает только энкодер виртуальных токенов перед входом: lr на порядок выше LoRA — 1e-3 … 1e-2
(в P-tuning v2 — 5e-3 … 1e-2), 20–100 виртуальных токенов (классификация — 10–30, генерация — больше), MLP-энкодер
128–512. Сходится медленнее: 5–15 эпох с ранним остановом. На моделях меньше ~10B и трудных задачах (NER, QA)
обычно уступает LoRA — для них лучше LoRA, если пользователь не выбрал P-tuning явно.
