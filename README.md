# LoRA factory

Агентная система автоматического дообучения LLM под NLP-задачи. Пользователь описывает задачу в веб-чате; система
уточняет постановку, подбирает модель под железо машины, находит и готовит датасет, подбирает конфигурацию
(LoRA / QLoRA / P-tuning, через Unsloth или PEFT), обучает адаптер, следит за обучением в реальном времени и выдаёт
адаптер, метрики на test и сравнение с baseline'ами.

Спецификация — [архитектура финал.md](архитектура финал.md). Код курсовой («Библиотека адаптеров для задач NLP»)
лежит в `src/*.py` и используется через обёртки: эвристика гиперпараметров (`config_gen.suggest_config`),
детектор языка (`dataset_work.detect_language`), промпт расширения запроса, настройки LLM-сервера (`settings`,
`dev.env`), формат промпта `Input: …\nTarget:` для моделей без шаблона чата (адаптеры совместимы с `check.py`).

## Запуск

### Docker и закрытый контур

Подготовьте каталог `models/` и положите туда модель в формате Transformers: `config.json`, веса
(`*.safetensors` или `pytorch_model*.bin`) и файлы токенизатора. В `docker-compose.yml` он подключается в
контейнер как `/models` только для чтения; `data/` хранит пользовательские загрузки, конфигурацию,
сессии, адаптеры и чекпоинты между пересозданиями контейнера.
В интерфейсе ползунок «Локальные / Hugging Face» переключает источник для новых задач и сохраняет
выбор в `data/model_source.json`. В локальном режиме панель «Модели» показывает инструкцию и поле
для пути `/models/имя-папки`: например, папку `models/my-model/` с `config.json`, всеми файлами весов
и токенизатора нужно скопировать в проект, затем нажать «Подключить модель». После переключения
источника или регистрации модели создайте новую сессию, чтобы список моделей в постановке обновился.
Для передачи GPU нужен Docker Compose 2.30+ с настроенной поддержкой NVIDIA GPU на хосте.

```bash
docker compose build
docker compose up -d
docker compose exec factory python -m factory register-model --path /models/my-model --lang ru
```

Вместо последней команды модель можно зарегистрировать через `POST /api/models/local` с JSON
`{"path":"/models/my-model","languages":["ru"]}`. API сразу добавляет её в выбор модели; после
регистрации через CLI перезапустите сервис (`docker compose restart factory`). Адрес чата —
`http://127.0.0.1:8000`; порт задаётся переменной `FACTORY_PORT`.

По умолчанию `FACTORY_OFFLINE=1`: поиск моделей и датасетов на HF отключён, из доступных моделей
показываются только зарегистрированные локальные. Пользователь загружает свой датасет через
интерфейс. Для агентов нужен OpenAI-совместимый LLM-сервер внутри вашей сети; укажите его адрес
через `OPENAI_SERVER__URL`, а имя модели — через `OPENAI_SERVER__DEFAULT_MODEL`.
`host.docker.internal:8001/v1` — значение по умолчанию для сервера на машине Docker. LLM-сервер
должен быть доступен из контейнера.
`src/dev.env` используется только при запуске без Docker и не копируется в образ. Для Docker
передайте `OPENAI_SERVER__URL`, `OPENAI_SERVER__KEY` и `OPENAI_SERVER__DEFAULT_MODEL` через
переменные окружения Compose или файл `.env` в корне проекта. Привязка к Windows-интерфейсу
`OPENAI_SERVER__BIND_INTERFACE` внутри контейнера отключена.

Если удалённый LLM-сервер доступен с Windows только через конкретный адаптер (например, из-за
VPN), запустите на Windows мост:

```powershell
.venv\Scripts\python.exe scripts\llm_bridge.py
```

Мост читает адрес, ключ и адаптер из `src/dev.env`, слушает только `127.0.0.1:8001` и принимает
запросы с тем же ключом. В корневом `.env` для Compose задайте
`OPENAI_SERVER__KEY` и `OPENAI_SERVER__DEFAULT_MODEL` из `src/dev.env`, а `OPENAI_SERVER__URL`
не задавайте: Docker использует `http://host.docker.internal:8001/v1`. Мост должен работать,
пока нужны вызовы агентов. Для LLM-сервера, доступного контейнеру напрямую, мост не требуется.

Если для задачи требуется BERTScore, укажите в `data/config.yaml`
локальный каталог модели как
`training.bert_score_model`:

```yaml
training:
  bert_score_model: /models/bert-score-model
```

При отсутствии каталога подтверждение такой задачи завершится понятной ошибкой.
Сборка образа требует доступ к индексам пакетов; для переноса в закрытую сеть сохраните и
перенесите готовый образ. Поддержка объединения нескольких датасетов пока представлена
контрактом `prep/merge.py` и ответом HTTP 501; синтез примеров уже реализован в `prep/augment.py`.

Без Docker можно выполнить `python -m factory register-model --path ПУТЬ --lang ru`, установив
`FACTORY_OFFLINE=1` и при необходимости `FACTORY_DATA_DIR`.

```bash
uv sync --inexact            # --inexact: не удалять пакеты, поставленные вне проекта
cd src
python -m factory build-catalog --lang ru   # офлайн: кэш каталога HF + эмбеддинги описаний (один раз)
python -m factory serve --port 8000         # веб-чат: http://127.0.0.1:8000, реестр запусков: /results
```

Windows (без WSL): то же из PowerShell, интерпретатор — `.venv\Scripts\python.exe`. torch с CUDA 12.8 ставится с
индекса PyTorch (`[tool.uv.sources]` в `pyproject.toml`: на PyPI под Windows только CPU-сборка), Triton — пакет
`triton-windows`. Flex attention Unsloth на Windows выключен (`UNSLOTH_ENABLE_FLEX_ATTENTION=0` в рабочем
процессе): с ним Gemma3 падала на оценке посреди обучения (CUDA illegal memory access) и училась в ~6 раз медленнее
(~500 против ~3000 токенов/с на RTX 3060). Рабочие процессы запускаются с `PYTHONUTF8=1`; для самого сервиса тоже лучше
`$env:PYTHONUTF8 = "1"`. Один `.venv` на Windows и WSL не работает — для WSL отдельное окружение:
`UV_PROJECT_ENVIRONMENT=.venv-wsl uv sync`.

LLM-сервер (OpenAI-совместимый, например vLLM) — в `src/dev.env` (`OPENAI_SERVER__URL`, `OPENAI_SERVER__KEY`,
`OPENAI_SERVER__DEFAULT_MODEL`). Если включён VPN в режиме TUN, а сервер доступен только напрямую,
`OPENAI_SERVER__BIND_INTERFACE=Ethernet` (имя адаптера или его IP) пускает запросы к LLM через физический адаптер
мимо туннеля; остальной трафик идёт как обычно. Роли, пороги детекторов и качества данных, лимиты, веса критериев — в
`data/config.yaml` (значения по умолчанию — `src/factory/core/config.py`). Стратегия подбора гиперпараметров:
`HPARAM_STRATEGY=heuristic|agent`. Графики: `MLFLOW_ALLOW_FILE_STORE=true mlflow ui --backend-store-uri data/mlruns`.

Стек (проверен 2026-10-23): torch 2.9.1 (CUDA 12.8), Unsloth 2026.10.7, transformers 5.17, trl 1.15, peft 0.21,
torchao 0.16, pydantic-ai 2.56. Подробности и причины версий — §6 спецификации.

## Задачи и метрики

Метрики задаёт реестр `data/registry/tasks.yaml`, а не LLM. Основная метрика выделена.

| Задача | Ответ модели | Метрики | Baseline'ы |
|---|---|---|---|
| Классификация текста | метка из набора | **macro-F1**, accuracy, weighted-F1, per-class | самый частый класс, исходная модель с промптом |
| Анализ тональности | метка тональности | **macro-F1**, accuracy, weighted-F1, per-class | то же |
| Суммаризация | резюме | **ROUGE-L**, ROUGE-1/2, chrF, BERTScore F1 | первые предложения входа, исходная модель |
| Генерация текста | ответ | **chrF**, BLEU, BERTScore F1, ExactMatch | копия входа, исходная модель |
| NER | «ТИП: текст; …» | **entity-F1**, entity-P/R (точное совпадение типа и текста), per-type | словарь сущностей из train, исходная модель |
| QA (экстрактивный) | фрагмент контекста | **token-F1**, ExactMatch (SQuAD, лучший из эталонов) | предложение, ближайшее к вопросу, исходная модель |

Датасеты NER читаются из токенов + BIO/IOB/BIOES-тегов, QA — из контекста, вопроса и ответов (SQuAD/SberQuAD).

## Агенты

- **A1 Intake** — уточняет постановку, подбирает модель из списка, отфильтрованного под VRAM/RAM/диск и замеренную
  скорость GPU (с рекомендацией и оценкой времени), ищет датасеты.
- **A2 DataPrep** — ReAct с целями качества (пустые, дубли, почти-дубли, мусор, выбросы длины, язык, баланс, метки,
  шум меток); не фиксирует рецепт, пока цели не выполнены или не обоснован отказ; 20 инструментов исследования
  и операций (`clean_text`, `map_labels`, `dedupe`, `filter`, `drop_label_noise`, `rebalance`, `augment` с
  синонимизацией, `undo`, …).
- **A3 HParam** — эвристики по типу задачи и объёму данных (QLoRA, Unsloth, LoRA, практика — `data/docs/hparams/`),
  похожие запуски, каждое решение со ссылкой на свидетельство; guard, пилот, бюджет GPU-часов.
- **A4 Monitor** — наблюдает за живым процессом (метрики, кривая val, конфигурация, история) и управляет им
  инструментами: снизить lr, ограничить градиент, частота оценки/лога, оценка и чекпоинт сейчас, досрочная остановка;
  команды подтверждаются процессом. Вызывается по аномалиям и на плановую проверку; пишет диагнозы раундов и итоговый.

## Что видно во время работы

- **Лента «что происходит сейчас»** под индикатором занятости в чате. В ней каждый шаг агентов: запрос к модели («думает», с таймером), вызов инструмента с аргументами («ищет почти-дубли (порог 0.9)», «меняет lr ×0.5 — причина») и его итог («не выполнено: мусор», «строк 400 → 386», «применено на шаге 182»). Туда же пишутся запуски рабочих процессов: baseline'ы, пилот, раунд, финальная оценка. Источник — `core/activity.py`: агенты запускаются через `agent.iter()`, шаги графа переводятся в строки.
- **Сколько осталось обучаться** — на панели обучения: шаг из скольких с прогресс-баром, оставшееся время и время окончания; оставшееся время продублировано в чате. Процесс обучения считает время по фактическому темпу раунда, оценки на val входят в темп (`eta_s`, `max_step` в `metrics.jsonl`). До первых точек показывается оценка по пилоту. Финальная оценка на test в это время не входит.

## Тесты

```bash
.venv/bin/python -m pytest -m "not integration"   # быстрые
.venv/bin/python -m pytest                        # + обучение крошечной модели в подпроцессах и сквозные сценарии
.venv\Scripts\python.exe -m pytest                # то же на Windows
```

Интеграционные тесты обучают крошечную Llama локально: LoRA, P-tuning, QLoRA, Unsloth LoRA и QLoRA, NER и QA,
продолжение раунда (lr не растёт), команды процессу, агент мониторинга, управляющий живым обучением, сквозные
сценарии Авто/Эксперт.

## Проверено на настоящей LLM

A1 (постановка с выбором модели под железо), A2 (чистка «грязной» выборки до выполнения всех целей), A3 (подбор
для NER со ссылками на заметки), A4 (реакция на взрыв градиента: клиппинг, снижение lr, проверка эффекта).
Полный цикл рабочего процесса на настоящей Qwen3-0.6B через Unsloth (RTX 3060): baseline'ы → пилот (2.5 тыс.
токенов/с, пик 4.1 ГБ) → раунд (48 шагов, ~1 мин) → test: macro-F1 1.00 против 0.33 у исходной модели и
мажоритарного класса, задержка ~430 мс. Сквозной сценарий через оркестратор с настоящей LLM целиком не прогонялся.
